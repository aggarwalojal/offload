# WhatsApp demo without inbound webhook configuration

This is an explicitly labelled **polling demo**, not a live webhook demonstration.
It reads real inbound messages from Twilio's authenticated Messages API every five
seconds and runs the existing database/AI pipeline. Whether the new trial exposes
its incoming messages through that API must be checked with the actual account.

1. Set `TWILIO_ACCOUNT_SID` and `TWILIO_AUTH_TOKEN` in `backend/.env` using real account
   credentials. Never commit them. Set `TWILIO_WHATSAPP_FROM` to the trial number shown
   in your Console, including `whatsapp:+` and no spaces. This differs from the old
   classic Sandbox number in the example configuration.
2. Join that trial from the phone already linked in Supabase.
3. Check credentials first. From the repo root:

```sh
source .venv/bin/activate
python -m backend.integrations.twilio.demo_poll --check
```

This only reads Twilio history and Supabase; it doesn't schedule or send anything.
If Twilio returns 401/403, fix credentials/access before proceeding. A successful
API response with no matching messages is not proof that trial inbound history is
available. Verify an actual incoming message reaches `whatsapp_inbox` in the next step.

4. Stop any separate `backend.jobs.worker` process while using this demo runner.
   Then run:

```sh
source .venv/bin/activate
python -m backend.integrations.twilio.demo_poll
```

5. Send a **new** WhatsApp text after the runner starts. Earlier messages aren't
   replayed. Incoming requests deduplicate by Twilio MessageSid. The runner catches
   up with messages received during its lifetime; restarting starts a fresh window.
6. Check Supabase's `whatsapp_inbox`. With AI unconfigured, its reply in
   `whatsapp_outbox.body` honestly says the service isn't connected. With Jia's
   agreed AI API and Ojal's OAuth connected, outcomes populate `time_entries`,
   `tasks`, and `agent_actions`, and the dashboard can refresh as usual.

No ngrok or public backend address is needed for this inbound transport. The
`TWILIO_WEBHOOK_URL` placeholder can remain in the env file because it is not used
by this runner. Dashboard API reads still require the standalone API process or the
teammates' integrated app to be running.

The new trial restricts API sends to Twilio-provided templates, so custom outgoing
replies are disabled by default and recorded as `blocked/demo_replies_disabled`.
Twilio may still send its Standard auto-reply; this isn't a TimeSlice confirmation.
Do not show it to judges as a reply generated by the app. The app's actual result
is in Supabase and the dashboard. Briefing jobs are not run in this demo mode.

Only with a compatible classic Sandbox or fully configured sender/account can you
opt in to actual custom replies using `--send-replies`. This does not unlock trial
features or bypass WhatsApp messaging restrictions. Leave this flag off for the
current trial. A webhook is still the intended production inbound transport.

## Stop or undo

Press **Ctrl+C** in the runner terminal to stop polling. It only starts when this
specific command is run; the normal API and worker do not import or start it.
Return to the normal `python -m backend.jobs.worker` command when using a working
webhook setup. No database migration, schema change or additional dependency was
introduced by the fallback.

Stopping doesn't undo activity/Google writes already executed through your AI service.
Those records remain real and need normal authorized deletion if you choose to remove
them. With AI unconfigured, this runner only creates inbox/outbox records.

The implementation is contained in `backend/integrations/twilio/demo_poll.py`, plus
its tests/documentation. You can leave these unused or remove them later. Your local
`.env` sender was corrected to the trial number in your screenshot; if you switch to
a different sender, update `TWILIO_WHATSAPP_FROM` to that sender's actual number.

Read-only API polling doesn't create extra WhatsApp messages. Message sends may be
subject to the account's existing trial limits/billing. The runner doesn't provision
services, buy a sender or upgrade an account.

References: [Twilio message history](https://www.twilio.com/docs/messaging/tutorials/how-to-retrieve-and-modify-message-history),
[current trial restrictions](https://www.twilio.com/docs/usage/trials/try-out-whatsapp).
